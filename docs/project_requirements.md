# Project Requirements Summary

This summary is based on the FURP handbook and the GitHub repository tutorial provided on 2026-06-08.

## Certificate Requirements

To receive the FURP certificate, all three requirements must be completed:

1. Attend more than 50% of all programme activities, including weekly meetings, workshops, and scheduled online or in-person sessions.
2. Submit a research poster or presentation PDF named `FURP_Showcase.pdf` in the repository root.
3. Present the poster at the Poster Showcase. In-person presentation is preferred; if attendance is impossible, a stand-in must present on the participant's behalf.

Missing any one of these requirements means the certificate is not awarded for this round.

## Research Track Requirement

For the research track, the minimum certification standard is:

- Successfully replicate a cited paper.
- Add at least 10% innovation beyond replication.
- Include benchmarking, validation, or another defensible method for showing the added contribution.

If changing project tracks, email the project lead with the subject `Project Transfer Request` and copy the supervising faculty member.

## GitHub Repository Requirements

The repository should be used for Agile-style project tracking. The expected structure is:

```text
docs/
|-- 00_weekly.md
`-- meeting_notes/
src/
FURP_Showcase.pdf
```

Required repository habits:

- Update `docs/00_weekly.md` every week with progress, challenges, and next steps.
- Log key meeting takeaways in `docs/meeting_notes/`.
- Keep project source code, experiments, and implementation files under `src/`.
- Place the final poster or presentation PDF in the repository root as `FURP_Showcase.pdf`.
- Use clear commit messages so the supervisor can see what changed and when.

## GitHub Visibility and Collaboration

The GitHub tutorial gives two acceptable ways for the supervisor and team members to view progress:

- Private repository: invite the supervisor or teammates as collaborators. Use `Read` permission for a supervisor who only needs to inspect progress, and `Write` permission for active collaborators.
- Public repository: make the repository visible to anyone with the link. This is simpler, but the repository must not contain passwords, keys, private information, or other sensitive files.

After the repository is created, send the GitHub repository URL to the supervisor.

## Leave and Withdrawal

Any leave of absence or withdrawal must be reported by email. Verbal or chat messages are not sufficient.

For leave:

- Email before the session when possible.
- State the date or dates and the reason.
- Remember that leave still affects the attendance percentage unless handled separately by the programme.

For withdrawal:

- Email the programme formally.
- This allows the project slot, records, and mentoring arrangements to be updated.
